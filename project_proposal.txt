# Project Context: Psychometric AI Coach

## 1. Project Identity
The **Psychometric AI Coach** is a specialized agentic planning system designed to help students prepare for the Psychometric Entrance Test. Unlike generic planners, it has deep domain knowledge of specific study tasks (Geometry, Analogies, English Vocabulary, etc.) and optimizes schedules based on cognitive load and learning best practices.

## 2. Core Architecture
The system follows a stateful **Interpreter -> Scheduler -> Verifier** pipeline, backed by a persistent JSON database.

### A. The Interpreter (`interpreter.py`)
- **Role**: Semantic Extraction & Normalization.
- **Function**: Converts natural language input into structured JSON.
- **Strict Logic**:
  - Maps user intent *strictly* to the `TASK_CATALOG`.
  - **Progressive Naming**: Appends numbers to base names (e.g., "Do geometry ch 5" -> `Geometry 5`).
  - **Prefixing**: Adds language prefixes (e.g., `ENG Vocabulary 1`) as defined in the catalog.
  - **Tagging**: Automatically assigns tags (Quantitative, Verbal, English) based on the canonical task name.

### B. The Scheduler (`scheduler.py`)
- **Role**: Strategic Time Orchestration.
- **Function**: Places "Floating Tasks" into "Empty Slots" around "Locked Anchors".
- **Intelligence**:
  - **The 3-Hour Rule**: Never schedules >3 hours of the same subject (e.g., Math) consecutively to prevent burnout.
  - **Peak Performance**: Prioritizes "Simulations" (3+ hours) for morning slots.
  - **Hard Constraints**: Respects `is_locked` flags and start/end times absolutely.

### C. The Verifier (`verifier.py`)
- **Role**: Algorithmic & Logical Safety.
- **Function**: Detects overlaps, invalid times, or missing fields before saving to the DB.

## 3. Data & State (`database.json`)
- **Single Source of Truth**: The frontend reads *only* from this file via the API.
- **Task Schema**:
  - `id`: Timestamp or Unique Int.
  - `name`: Strict Canonical Name (e.g., "Geometry 1").
  - `tag`: Driven by `task_catalog.py` (e.g., "Quantitative").
  - `status`: `pending` (in bank) or `scheduled` (on calendar).
  - `scheduled_day/start/end`: populated only if `status == "scheduled"`.

## 4. Design System & UI
A strict, unified design system ensures consistency across the React Frontend.

### Color Coding (CSS Variables in `index.css`)
All components (`TaskBank.jsx`, `CalendarView.jsx`) MUST use these variables:
- 🔴 **Quantitative**: `--tag-bg-quantitative` / `--tag-border-quantitative` (Red)
- 🟡 **Verbal**: `--tag-bg-verbal` / `--tag-border-verbal` (Gold/Yellow)
- 🔵 **English**: `--tag-bg-english` / `--tag-border-english` (Blue)
- 🟣 **Simulation**: `--tag-bg-simulation` / `--tag-border-simulation` (Purple)
- 🟢 **Essay**: `--tag-bg-essay` / `--tag-border-essay` (Green)
- ⚓ **Class**: `--tag-bg-class` / `--tag-border-class` (Navy)

### Task Bank
- **Logic**: Displays *only* tasks with `status != "scheduled"`.
- **Empty State**: Explicit "Building your bank..." message if no pending tasks exist.

### Calendar View
- **Logic**: Displays *only* tasks with `status == "scheduled"`.
- **Format**: Expects 3-letter day codes (`Mon`, `Tue`) to match column headers.

## 5. Typical Workflows for Agents
- **Adding a Feature**: Always update `task_catalog.py` first if it involves new task types.
- **Fixing Scheduling**: Check `scheduler.py` prompt heuristics.
- **UI Tweaks**: Respect `index.css` variables; do not hardcode hex values.
- **Debugging**: If tasks vanish, check `database.json` for `status` vs. `scheduled_day` mismatches.

This document serves as the primary context for maintaining and extending the Psychometric AI Coach.
